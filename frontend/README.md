# NeVpade — клієнтська частина

Вебінтерфейс менеджера вантажоперевезень: рейси, клієнти, автопарк, графік машин, карта, завдання, чат команди й аналітика.
Технології: HTML, SCSS, JavaScript (ES-модулі), Vite, Chart.js, SortableJS, Google Maps API.

## Запуск

```bash
npm install
copy .env.example .env      # Windows (macOS/Linux: cp .env.example .env)
npm run dev                 # http://localhost:5173
```

| Команда | Що робить |
|---|---|
| `npm run dev` | сервер розробки з оновленням сторінки «на льоту» |
| `npm run build` | збірка в `dist/` (усі сторінки, CSS і JS мінімізовані) |
| `npm run preview` | перегляд зібраної версії з `dist/` |

## Налаштування (`.env`)

| Змінна | За замовчуванням | Призначення |
|---|---|---|
| `VITE_USE_MOCK` | `true` | `true` — працює без сервера на демо-даних; `false` — запити йдуть на бекенд |
| `VITE_API_URL` | `http://localhost:8000/api` | адреса API Іри |
| `VITE_MOCK_DELAY` | `150` | штучна затримка моків, мс (`0` — миттєво) |
| `VITE_GOOGLE_MAPS_KEY` | — | ключ Google Maps; без нього карта показує спрощену схему маршруту |
| `VITE_GOOGLE_CLIENT_ID`, `VITE_FACEBOOK_APP_ID` | — | вхід через Google / Facebook |

### Режим демо-даних

Демо-дані лежать у `src/js/mock/*.json`, а зміни (нові рейси, клієнти, машини) зберігаються в `localStorage` браузера.
Копії документів (фото, PDF) — в IndexedDB. Щоб скинути все до початкових даних, очистіть дані сайту в браузері
або збільште `MOCK_VERSION` у `src/js/api/mock-store.js`.

Демо-вхід: будь-яка пошта й будь-який пароль. Перший користувач (`usr_01`) — **керівник**.

### Імпорт з Della

Під час розробки Vite проксіює `/della/*` → `https://della.ua/*` (див. `vite.config.js`), тож сторінку пошуку
біржі можна розібрати прямо в браузері. У робочій версії це робить бекенд: `GET /api/import/della?path=…`.

## Вхід через Google

Одна кнопка і для входу, і для реєстрації. Новий користувач після Google потрапляє на сторінку
**«Завершіть реєстрацію»** (`pages/onboarding.html`): ім'я, компанія (створити або приєднатися за кодом), телефон →
SMS-код → робочий простір. Хто вже зареєстрований — одразу в аналітику. Як налаштувати ключ Google і що робить
бекенд — у [`docs/api-contract.md`](../docs/api-contract.md), розділ «Вхід і реєстрація через Google / Facebook».

У режимі демо-даних кнопка Google імітує вхід: перший раз — як новий користувач (покаже «Завершіть реєстрацію»),
після завершення — як наявний.

## Ролі

| Дія | Менеджер | Керівник |
|---|---|---|
| Створювати рейси, клієнтів, машини, водіїв | ✓ | ✓ |
| Змінювати, видаляти, передавати рейс | лише свій | будь-який |
| Видаляти машини, водіїв, клієнтів | — | ✓ |
| Змінювати ролі колег | — | ✓ |
| Нагадування про оплати | свої рейси | уся компанія |

Інтерфейс лише ховає недоступні кнопки — перевіряє права сервер (відповідь `403`).

## Структура

```
frontend/
├── index.html            лендинг
├── 404.html              сторінка «не знайдено»
├── pages/                сторінки застосунку (по одному HTML на розділ)
├── src/
│   ├── partials/head.html   спільний <head>, підставляє плагін у vite.config.js
│   ├── scss/             стилі: _variables (токени теми) + модуль на кожен розділ
│   └── js/
│       ├── api/          запити до сервера; у кожному — мок для автономного режиму
│       ├── mock/         початкові демо-дані (JSON)
│       ├── pages/        логіка сторінок
│       ├── utils/        спільне: макет, форматування, іконки, нагадування, CSV, друк
│       └── i18n/         англійський переклад (uk — мова за замовчуванням)
└── vite.config.js
```

Формат запитів і відповідей узгоджено з бекендом у [`docs/api-contract.md`](../docs/api-contract.md).

## Що варто обговорити з бекендом

- **Токен.** Зараз JWT лежить у `localStorage` (просто для курсової, але доступний будь-якому скрипту на сторінці).
  Надійніше, щоб сервер ставив його в cookie `HttpOnly; Secure; SameSite=Strict` — тоді в `api/client.js`
  достатньо додати `credentials: 'include'` і прибрати заголовок `Authorization`.
- **Розрахунки.** Аналітика, борги й собівартість у моках рахуються на фронті (`utils/economics.js`);
  на сервері мають бути ті самі формули, щоб цифри збігались.

## Хостинг

Сайт — набір статичних сторінок із `dist/`. Сервер має віддавати `404.html` на невідомі адреси
(Netlify / GitHub Pages роблять це самі; для nginx — `error_page 404 /404.html;`).
