# NeVpade — клієнтська частина

Вебінтерфейс менеджера вантажоперевезень: рейси, клієнти, автопарк, графік машин, карта, завдання, чат команди й аналітика.
Технології: HTML, SCSS, JavaScript (ES-модулі), Vite, Chart.js, SortableJS, Google Maps API.

## Запуск

```bash
npm install
copy .env.example .env      # Windows (macOS/Linux: cp .env.example .env)
npm run dev                 # http://localhost:5173
```

| Команда | Що робить |
|---|---|
| `npm run dev` | сервер розробки з оновленням сторінки «на льоту» |
| `npm run build` | збірка в `dist/` (усі сторінки, CSS і JS мінімізовані) |
| `npm run preview` | перегляд зібраної версії з `dist/` |

## Налаштування (`.env`)

| Змінна | За замовчуванням | Призначення |
|---|---|---|
| `VITE_USE_MOCK` | `true` | `true` — працює без сервера на демо-даних; `false` — запити йдуть на бекенд |
| `VITE_API_URL` | `http://localhost:8000/api` | адреса API Іри |
| `VITE_MOCK_DELAY` | `150` | штучна затримка моків, мс (`0` — миттєво) |
| `VITE_GOOGLE_MAPS_KEY` | — | ключ Google Maps; без нього карта показує спрощену схему маршруту |
| `VITE_GOOGLE_CLIENT_ID` | — | вхід менеджерів через Google |

### Режим демо-даних

Демо-дані лежать у `src/js/mock/*.json`, а зміни (нові рейси, клієнти, машини) зберігаються в `localStorage` браузера.
Копії документів (фото, PDF) — в IndexedDB. Щоб скинути все до початкових даних, очистіть дані сайту в браузері
або збільште `MOCK_VERSION` у `src/js/api/mock-store.js`.

Демо-вхід: на сторінці входу є список **демо-акаунтів** компанії «Західтранс», пароль усіх `Manager2026`:
власник **Ковальчук Андрій** (`a.kovalchuk@nevpade.ua`, код власника `OWN-4821-7KQP`) і п'ятеро менеджерів.
У кабінеті власника вже чекає одна демо-заявка (Бондар Марія). Щоб пройти вступ повністю: зареєструйте менеджера
з кодом `NVP-4821` (коди підтвердження в моках — `123456`), вийдіть, увійдіть як власник і прийміть заявку.
Будь-яка інша пошта на вкладці «Менеджер» входить як демо-менеджер (`usr_01`).

### Імпорт з Della

Під час розробки Vite проксіює `/della/*` → `https://della.ua/*` (див. `vite.config.js`), тож сторінку пошуку
біржі можна розібрати прямо в браузері. У робочій версії це робить бекенд: `GET /api/import/della?path=…`.

## Вхід через Google

Лише для менеджерів (власник входить з кодом власника). Одна кнопка і для входу, і для реєстрації. Новий користувач
після Google потрапляє на сторінку **«Завершіть реєстрацію»** (`pages/onboarding.html`): ім'я, код запрошення компанії,
телефон → SMS-код → заявка власнику → робочий простір після його підтвердження. Хто вже зареєстрований — одразу в аналітику. Як налаштувати ключ Google і що робить
бекенд — у [`docs/api-contract.md`](../docs/api-contract.md), розділ «Вхід і реєстрація менеджера через Google».

У режимі демо-даних кнопка Google імітує вхід: перший раз — як новий користувач (покаже «Завершіть реєстрацію»),
після завершення — як наявний.

## Ролі: менеджер і власник — два окремі інтерфейси

| | Менеджер | Власник компанії |
|---|---|---|
| Реєстрація | `pages/register.html`: код запрошення компанії (також через Google) → **заявка, яку підтверджує власник** | `pages/register-owner.html`: назва й місто компанії; лише пошта й пароль. **Компанію створює тільки власник** |
| Вхід | пошта + пароль (або Google) | вкладка **«Власник»**: пошта + пароль + **код власника** `OWN-XXXX-XXXX` |
| Інтерфейс | аналітика, рейси, клієнти, графік, карта, автопарк, завдання, команда, чат | **кабінет власника** (темно-зелене меню): огляд, менеджери, фінанси, компанія |
| Що може | вести свої рейси, машини, водіїв, клієнтів, завдання | приймати й відхиляти заявки на вступ, бачити показники компанії й кожного менеджера, звіт в Excel, змінити назву й місто, **код запрошення (бачить лише власник)**, прибрати менеджера (з передачею його рейсів колезі), передати компанію |

**Вступ менеджера.** Менеджер реєструється з кодом запрошення, підтверджує пошту й телефон і бачить сторінку
«Чекаємо підтвердження власника» (`pages/pending.html`, перевіряє статус кожні 15 с). Власник бачить заявку в
«Менеджерах» (лічильник біля пункту меню й блок «Потребує уваги» на огляді) і приймає або відхиляє її. Відхилений
менеджер може надіслати заявку з іншим кодом. Facebook-вхід прибрано.

**Код власника** — другий фактор входу: без нього в кабінет не зайти навіть з правильним паролем. Його показують
один раз після реєстрації (вікно не закривається, доки не підтвердиш, що зберіг). Забув — «Забули код власника?» на
сторінці входу (новий код приходить на пошту). У кабінеті «Компанія» можна видати новий код (потрібен пароль).
Після 5 невдалих спроб вхід власника призупиняється на 15 хвилин.

Сторінки розведені: менеджера не пускає в `pages/owner*.html` («Цей розділ доступний лише власнику компанії»),
власника з робочих сторінок одразу переводить у кабінет. Роль у браузері — лише кеш: на кожній сторінці фронт звіряє
її з `GET /auth/me`. Справжній захист — на сервері (`403 owner_only` / `manager_only`), див. `docs/api-contract.md`.

## Структура

```
frontend/
├── index.html            лендинг
├── 404.html              сторінка «не знайдено»
├── pages/                сторінки застосунку (по одному HTML на розділ)
├── src/
│   ├── partials/head.html   спільний <head>, підставляє плагін у vite.config.js
│   ├── scss/             стилі: _variables (токени теми) + модуль на кожен розділ
│   └── js/
│       ├── api/          запити до сервера; у кожному — мок для автономного режиму
│       ├── mock/         початкові демо-дані (JSON)
│       ├── pages/        логіка сторінок
│       ├── utils/        спільне: макет, форматування, іконки, нагадування, CSV, друк
│       └── i18n/         англійський переклад (uk — мова за замовчуванням)
└── vite.config.js
```

Формат запитів і відповідей узгоджено з бекендом у [`docs/api-contract.md`](../docs/api-contract.md).

## Що варто обговорити з бекендом

- **Токен.** Зараз JWT лежить у `localStorage` (просто для курсової, але доступний будь-якому скрипту на сторінці).
  Надійніше, щоб сервер ставив його в cookie `HttpOnly; Secure; SameSite=Strict` — тоді в `api/client.js`
  достатньо додати `credentials: 'include'` і прибрати заголовок `Authorization`.
- **Розрахунки.** Аналітика, борги й собівартість у моках рахуються на фронті (`utils/economics.js`);
  на сервері мають бути ті самі формули, щоб цифри збігались.

## Хостинг

Сайт — набір статичних сторінок із `dist/`. Сервер має віддавати `404.html` на невідомі адреси
(Netlify / GitHub Pages роблять це самі; для nginx — `error_page 404 /404.html;`).
